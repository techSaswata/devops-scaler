==================== 2. CREATE AN APACHE2 CONTAINER USING THE HOST NETWORK ====================
$ docker run -d --name apache-host --network host httpd:2.4
ccbc18d525759875869977040ae11b4146fd33e2ae5b965713edd55b98915b1b

--- note the PORTS column is EMPTY ---
$ docker ps --filter name=apache-host
NAMES         IMAGE       STATUS         PORTS
apache-host   httpd:2.4   Up 3 seconds   

>> There is no '0.0.0.0:80->80/tcp' mapping because there is nothing to map.
>> With --network host the container does not get its own network namespace;
>> it shares the host's. Apache binds port 80 ON THE HOST DIRECTLY.
>> This is also why '-p 80:80' is meaningless (and ignored) with host networking.

==================== 3. PROOF: the container shares the HOST's network namespace ====================
--- a normal BRIDGE container gets its own private IP ---
$ docker exec apache-bridge hostname -i     # bridge container
172.17.0.9
$ docker inspect apache-bridge --format '{{.NetworkSettings.IPAddress}}'
172.17.0.9

--- the HOST-network container has NO container IP of its own ---
$ docker inspect apache-host --format '{{.NetworkSettings.IPAddress}}'
[]  <- empty

$ docker exec apache-host hostname -i       # host-network container
192.168.65.3
$ docker exec apache-host hostname
docker-desktop
>> It reports the HOST's hostname and the HOST's IP, not a 172.17.x.x address.

==================== 4. ACCESS THE APACHE WEBSITE ON PORT 80 ====================
--- from another container that ALSO uses the host network ---
$ docker run --rm --network host nettools curl -s -o /dev/null -w 'HTTP %{http_code}' http://localhost:80/
HTTP 200

$ docker run --rm --network host nettools curl -s http://localhost:80/
<!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.01//EN" "http://www.w3.org/TR/html4/strict.dtd">
<html>
<head>
<title>It works! Apache httpd</title>
</head>
<body>
<p>It works!</p>
</body>
</html>
>> SUCCESS. Apache is answering on port 80 of the host network namespace,
>> reachable at plain 'localhost:80' with no port publishing at all.

--- for contrast: a BRIDGE container's localhost is its OWN, so this fails ---
$ docker run --rm nettools curl -s --max-time 3 http://localhost:80/   (expected to FAIL)
curl: (7) Failed to connect to localhost:80 after 0 ms: Could not connect to server
>> Correct: in a bridge container, 'localhost' means that container itself.

==================== 5. HOW THIS LOOKS ON macOS  (an important caveat) ====================
$ curl --max-time 5 http://localhost:80/     # from macOS itself
HTTP 000

>> On macOS this returns 000 (no connection), and that is EXPECTED, not a broken demo.
>>
>> Docker Desktop does not run containers on macOS directly -- it runs a Linux VM.
>> "--network host" means "the HOST inside that VM". So Apache really is on port 80
>> of the Linux host's network namespace (proved in step 4), but macOS is a separate
>> machine from Docker's point of view, and there is no published port to forward.
>>
>> On a native Linux Docker host, "curl http://localhost:80" from the host shell
>> would return 200 immediately.
>>
>> Docker Desktop 4.34+ ships an opt-in host-networking feature
>> (Settings -> Resources -> Network -> "Enable host networking") that bridges this
>> gap. It is not enabled here, and turning it on requires restarting Docker Desktop.

==================== 6. WHEN TO USE HOST NETWORKING ====================

  PROS
    - No NAT hop, so slightly lower latency and higher throughput.
    - The container can bind ANY port without publishing it.
    - Needed for tools that must see the host's real interfaces:
      network monitors, tcpdump-style capture, DHCP servers, mDNS/discovery.

  CONS
    - NO ISOLATION. The container can bind any port and see all host traffic.
    - Port conflicts: two containers cannot both bind port 80.
    - Not portable: --network host is Linux-only in the strict sense; on
      Docker Desktop it means the VM's host, as shown above.
    - Loses Docker's DNS-by-container-name.

  DEFAULT ADVICE: use bridge + -p. Reach for host networking only when you have
  a specific reason, and know that you are trading isolation for it.
