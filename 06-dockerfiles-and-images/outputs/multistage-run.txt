############ 8. PROOF the final image has no shell / no OS ############
$ docker run --rm --entrypoint /bin/sh multistage-app:latest   (expected to FAIL)

Run 'docker run --help' for more information

$ docker run --rm --entrypoint /bin/ls multistage-app:latest /   (expected to FAIL)
docker: Error response from daemon: failed to create task for container: failed to create shim task: OCI runtime create failed: runc create failed: unable to start container process: error during container init: exec: "/bin/ls": stat /bin/ls: no such file or directory: unknown

Run 'docker run --help' for more information

$ docker exec multistage-app sh    (cannot debug a scratch container this way)
OCI runtime exec failed: exec failed: unable to start container process: exec: "sh": executable file not found in $PATH: unknown

>> There is no shell, no ls, no package manager, no libc in the image.
>> Nothing to exploit and nothing to patch — that is the security win of
>> a scratch-based multi-stage build, on top of the size win.
